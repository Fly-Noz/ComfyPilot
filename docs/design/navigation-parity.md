# S7 · 两端页面地图与导航约定

日期：2026-10-23

关联：`.scratch/s7-parity/issues/05-navigation-parity.md`

## 结论

保留两端的平台外壳，不追求页面结构或像素一致：

- Android：顶栏 + 独立页面 + 产物全屏对话框；
- 鸿蒙：单页 + 顶部连接区 + “工作流 / 任务 / 日志”页签 + 产物面板。

需要统一的是**信息层级**和**返回语义**：

1. 连接是前置条件，连接后才进入工作流/任务；
2. “工作流”和“任务”是同级主入口，工作流详情嵌套在“工作流”下；
3. 从详情去看任务，返回时必须回到详情，且不能丢掉未提交的字段、页签和展开状态；
4. 两端详情页都要能看“输入”和“采样/产物预览”；
5. 任务 → 产物列表 → 单份产物预览的层级一致，对话框/页面只是平台表现；
6. 诊断/日志是次级入口，不占用主流程。

## 核心路径对照

| 核心任务 | Android | 鸿蒙 | 结论 |
|---|---|---|---|
| 连接 | Connect 页 | 顶部连接区 | 平台表现可不同；未连接时都不应显示空的主页面 |
| 选工作流 | Catalog → Detail | 工作流页签 → 详情 | 一致 |
| 改字段 / 开关节点图 | Detail 输入页签 | 详情内节点卡片 | 一致 |
| 提交 | Detail 底部按钮 | 详情内按钮 | 一致 |
| 看实时进度 | Detail 预览页签 / Tasks | Tasks 采样预览卡片 | 鸿蒙详情页缺入口 |
| 看产物 | Detail 预览 / Tasks → 对话框 | Tasks → 产物面板 | 鸿蒙详情页缺入口 |
| 下载 | 产物对话框 | 产物面板 | 一致 |
| 返回列表 | 系统返回 / 顶部返回 | 详情“返回” | 一致 |
| 看任务 | Catalog / Detail 顶栏 | 任务页签 | Android 从详情进入会丢状态 |
| 诊断 / 日志 | Diagnostics（次级） | 日志页签（主入口） | 鸿蒙应降为次级入口 |

## 交互约定

1. **详情是保留态**：从详情进入任务页再返回，字段 override、节点图选择、当前页签、展开的节点和滚动位置都应保留。
2. **任务返回来源**：从详情进入任务，返回详情；从工作流目录进入任务，返回目录。不能一律回目录。
3. **详情双页签**：Android 保持“输入 / 预览”；鸿蒙在详情内补“输入 / 预览”，预览至少包含活动任务进度、采样图、最近产物入口。
4. **提交后留在详情**：提交成功后两端都停留在当前详情并切到预览，不自动跳到独立任务页。
5. **产物层级**：任务 → 产物列表 → 单份预览；返回逐级回退。Android 用全屏对话框、鸿蒙用全屏面板都可以。
6. **诊断入口**：诊断/日志不是主流程页签；保留在连接页、任务页或设置的次级入口。鸿蒙“日志”页签可以保留为调试能力，但不作为正式产品的第三个主入口。
7. **系统返回**：平台系统返回遵循平台惯例；页面内显式返回必须符合上面的来源关系。

## 差异处置

### 必须补齐

- **Android 详情往返任务丢状态**：`ComfyPilotApp` 当前把 Tasks 当独立页面，系统返回和顶部返回都回 Catalog；`DetailBody` 的 `remember` 状态在离开组合后丢失。
- **鸿蒙详情没有预览/产物入口**：实时预览只在“任务”页签，提交后还会自动跳到任务页签，和 Android 的“留在详情看预览”不一致。
- **鸿蒙工作流详情没有产物入口**：完成后必须切到任务页签才能打开产物。

### 保留为平台特性

- Android 用对话框展示产物，鸿蒙用全屏面板；
- Android 用顶部按钮，鸿蒙用页签；
- 两端视觉、间距和控件样式不统一；
- 系统返回手势/按键的具体行为由平台决定，页面内显式返回遵循本文约定。

### 暂不处理

- 连接页是否做成完全一致的阻塞页；
- 日志/诊断页面是否合并为同一套组件；
- 底部导航、路由库或 ArkUI Navigation 的引入。
