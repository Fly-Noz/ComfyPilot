# 05 · 两端页面结构与导航决策

Status: needs-triage
Type: task

## 问题

安卓是“工作流列表 → 工作流详情页（输入/预览）→ 任务列表 → 产物弹层”；鸿蒙是“工作流/任务/日志三个页签 + 产物全屏页”。两端能力接近，但用户切换设备时要重新学习路径。

## 范围

- 列出两端的核心路径：连接、选工作流、改字段、提交、看进度、看产物、下载；
- 决定哪些差异保留为平台特性，哪些必须统一；
- 若统一，优先统一信息层级（列表/详情/任务/产物的关系），不追求像素一致；
- 输出一份页面地图和交互约定，再评估改造量。

## 验收

- 文档明确每个核心任务在两端的入口和返回路径；
- 不存在“同一功能在一端找不到入口”的情况；
- 改造计划排到具体 issue，不在本 issue 直接大改 UI。
