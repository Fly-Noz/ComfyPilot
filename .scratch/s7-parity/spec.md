# S7 · 跨端工作流交互对齐

Status: needs-triage

## 背景

S6 完成了鸿蒙侧的工作流目录、详情、图启停、置顶、提交和产物。两端现在能完成同一件事，但操作路径和部分能力仍不同：

- 安卓在 UI 里直接调用 `PromptBuilder` / `WorkflowFields`，鸿蒙走共享的 `WorkflowUi`；
- 安卓有本机图片选择与 `/upload/image`，鸿蒙只能填写服务端已有的图片名；
- 安卓详情页有实时预览，鸿蒙没有；
- 安卓能内嵌播放视频，鸿蒙目前只提供下载；
- 两端的页面结构不同（安卓“列表 → 详情页”，鸿蒙“工作流/任务/日志”三个页签）。

S6 收尾时已经先对齐了会影响提交正确性的规则：

- 两端都给 `SaveImage` 的 `filename_prefix` 追加每次提交的唯一短 token，避免产物互相覆盖；
- 安卓改为和鸿蒙一样：不可提交时按钮置灰，并在按钮上方显示阻断原因；
- 鸿蒙补上了警告提交前的“仍然提交”确认；
- 两端都只在 ComfyUI 返回 `prompt_id` 后显示绿色“已提交”。

## 目标

1. 同一工作流在两端给出相同的“能不能提交、为什么不能提交、有哪些警告、哪些节点会执行”的判断。
2. 这些判断只维护一份，UI 只负责渲染；允许两端的页面结构和视觉不同。
3. 逐步补齐会影响实际使用的功能差异，而不是先做像素级统一。

## 非目标

- 不要求 ComfyUI 请求/响应格式发生变化；
- 不要求两端使用同一套 UI 框架或同一套页面结构；
- 不在这个阶段引入新的工作流编辑能力。

## 建议顺序

1. `01-shared-workflow-decisions.md`：先收敛共享决策层，避免后续每个修复都改两遍；
2. `02-harmony-image-upload.md`：补鸿蒙的本机图片上传；**已完成并真机验证**；
3. `03-harmony-live-preview.md`：评估并补鸿蒙实时预览；
4. `04-harmony-media-playback.md`：决定视频/音频是内置播放还是保持下载；
5. `05-navigation-parity.md`：最后再决定页面结构是否需要统一。

## 完成标准

- 两端对同一份工作流、同一组 overrides/图开关，得到相同的 `canSubmit`、阻断原因和警告集合；
- 安卓与鸿蒙的提交前确认策略一致；
- 新增的跨端规则有共享层测试，不依赖某一端的 UI 测试才能发现问题；
- 文档明确哪些差异是“平台特性”，哪些是“待补齐功能”。
